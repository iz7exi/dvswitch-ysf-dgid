===============================================================================
 YSF DG-ID for DVSwitch Mobile - INSTALLATION
===============================================================================

WHAT IT DOES
------------
Adds a "YSF DG-ID" entry to the DVSwitch Mobile menu. Selecting a value writes
Options=nn in YSFGateway.ini, restarts the gateway and re-links the room. The
callsign stays clean: the DG-ID is carried in the Options, not in a suffix.


TWO PARTS, IN ORDER
-------------------
1) build_ysfgateway_options.sh - patched YSFGateway. Stock YSFGateway sends the
   Options only on a Startup= link, never on the remote command DVSwitch uses
   to link a room. The patch adds that. WITHOUT IT the DG-ID has no effect.

2) dvsm_ysf_dgid.sh - the menu.


REQUIREMENTS
------------
- DVSwitch with Analog_Bridge and MMDVM_Bridge
- DVSwitch advanced menu (/opt/Analog_Bridge/dvsm.sh)
- YSFGateway managed by systemd
- git + build-essential (the build script installs them if missing)
- a reflector with DG-ID management (pYSFReflector3)


STEP 1 - COPY THE FILES TO THE NODE
-----------------------------------
scp build_ysfgateway_options.sh dvsm_ysf_dgid.sh root@NODE_IP:/root/
(from Windows/PuTTY use pscp; or paste each file with:  cat > /root/FILE << 'END' )


STEP 2 - BUILD THE PATCHED YSFGATEWAY
-------------------------------------
    chmod +x /root/build_ysfgateway_options.sh
    /root/build_ysfgateway_options.sh

It compiles on the node (a few minutes on ARM), saves the current binary and
installs the patched one. If the service does not restart it rolls back by
itself. To undo:  /root/build_ysfgateway_options.sh --rollback


STEP 3 - INSTALL THE MENU
-------------------------
    chmod +x /root/dvsm_ysf_dgid.sh
    /root/dvsm_ysf_dgid.sh

Different paths/service names:
    AB_DIR=/opt/Analog_Bridge YSF_INI=/opt/YSFGateway/YSFGateway.ini \
    SERVICE_YSF=ysfgateway SERVICE_AB=analog_bridge /root/dvsm_ysf_dgid.sh

To remove the menu:  /root/dvsm_ysf_dgid.sh --uninstall


STEP 4 - USE IT
---------------
Reconnect the app, switch to YSF mode, link a room BY ID (not by IP), then:

    main menu -> YSF DG-ID -> band of ten -> value

The display shows WAIT DG-ID nn then OK DG-ID nn. The callsign stays clean;
the DG-ID is in Options.


CHECKS, over ssh
----------------
    grep -n "^Callsign\|^Options" /opt/YSFGateway/YSFGateway.ini
      -> Callsign clean, Options=nn;

    tail -n 20 /var/log/mmdvm/YSFGateway-$(date +%Y-%m-%d).log


LINK BY ID, NOT BY IP
---------------------
Every room entry must carry the numeric ID from YSFHosts.txt:
    22273|||C4FM_BAT                 <- works
    82.85.236.36:42000|||C4FM_BAT    <- DG-ID has no effect
Find the ID:  grep -n "<address>" /var/lib/mmdvm/YSFHosts.txt


NOTES
-----
- works in YSF MODE ONLY
- DG-ID 00 removes Options: back to the reflector default
- the DG-ID must be ACTIVE on the reflector
- the setting survives a reboot; the room link does not


YCS SERVERS - LIMITATION
------------------------
On YCS you get connection, DG-ID registration and RX, but NOT TX on a chosen
DG-ID. YCS routes the voice by the DG-ID in each frame's FICH, and MMDVM_Bridge
always transmits with FICH DG-ID 0 with no way to change it (a radio or Z3DMR
set the FICH, DVSwitch does not). On pYSFReflector3 the DG-ID works fully.
